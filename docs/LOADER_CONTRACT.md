# 可选加载器接口

公开仓库不提供远程进程注入器。优先在自有应用中由应用自身加载 `libue4trace.so`，或者使用 `native/tests/fixture_main.cpp` 的自加载模式验证。

仅加载库会启动观察器 socket；还需要通过 configure 验证目标及配置后才能安装 Hook。

## 自行提供外部加载器

只有在具备目标授权和工具使用/再分发权限时，才应把自己构建的 Android ARM64 可执行文件放到本地 `assets/inject`，或原生构建产物目录中供 Windows 打包脚本复制。

后端调用接口为：

```text
inject <target-pid> <absolute-library-path> --path-only
```

该文件必须支持这个接口，不要把任意第三方二进制改名后直接使用。后端以当前已验证的 PID、starttime、模块路径和 Build ID 作为部署身份；库将置于目标应用的私有文件目录。

- 返回 0 只表示加载命令成功，后端仍必须获得有效 hello 并完成 configure。
- 非零返回、超时、中断或包含 `TARGET_STATE_UNCERTAIN` 的输出都不能作为安全恢复的证明。
- 注入命令发出前，后端写入持久状态标记；只有握手与 configure 全部成功才清除。同一 PID/starttime 的未确认尝试不会被自动重试。
- 不得自动修改 SELinux、关闭保护、重启目标、隐藏模块或循环尝试加载策略。
- 操作者有责任确认寄存器、线程、资源和失败路径的处理；本接口不为第三方加载器作安全保证。

## 构建身份

公开版采集器的身份包含固定依赖提交。旧本地原型及其它依赖构建不能被默认视为兼容。不要为跳过错误而随意添加兼容白名单。

同一采集器实例按完整配置 JSON 判断配置身份。若修改了任何字段，包括说明元数据，应在新的目标进程中重新加载并验证。
